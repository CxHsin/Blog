随着近几个月国内外 agent 产品的爆发，最近也看到了很多关于 agent 产品形态变化的讨论和 blog，心里有感，就阐述一下我的理解。

## 一、agent 产品变化的本质

首先，我认为 agent 产品变化的本质是 **信任** 的变化。

最开始，我们通过 Web 端与模型对话，让它回答问题、生成内容；后来，我们开始让 Coding Agent 操作本地电脑，直接修改文件、执行命令；再到如今，越来越多的 Personal Agent 开始尝试长期运行，在云端持续处理任务，并在需要时主动与我们交互。

这几个阶段的区别，不只是交互界面从 Web 变成了 IDE，再变成云端 Agent。

更重要的是，人类与 Agent 之间的分工发生了变化：从人类亲自执行、Agent 提供帮助，到 Agent 自主执行任务，再到人类将一批任务委托给 Agent，由它持续推进。

当然，这一切的前提，是模型能力、工程基础设施和产品机制逐渐成熟，让我们有理由相信 Agent 能够把事情做好。

## 二、Web 端

在最初时，ChatGPT 继往开来，如盘古开天向人类展示了什么叫 agent 产品（严格来讲最开始的时候并不能算 agent 产品）。

以编码为例，当时的典型工作方式仍然是：向 ChatGPT 提问，复制生成的代码，再粘贴到本地 IDE 中运行和调试。

模型与实际工作环境之间存在一道明显的边界。

在这个阶段，我们对于 agent 产品（模型）是不太放心的，所以就仅以一个网页的形式进行问答，他并不能对外部世界产生副作用。

## 三、本地 IDE / 终端

接下来，以 Cursor、GitHub Copilot、Codex、Claude Code 等产品为代表，模型开始逐渐进入我们的开发环境，获得直接操作代码和执行任务的能力。

当然，这不是一个严格线性的产品演进过程，不同形态至今仍然共存。但从人机协作方式来看，大致可以分成几个阶段。

最开始，以 Cursor 早期版本为例，按下 Tab 键，对代码进行补全。

接下来，就是以 VS Code 中的 Copilot 为首的侧边栏对话式，一问一答看到 agent 编写代码。

到了 Codex、Claude Code 这类 Coding Agent，交互方式又发生了变化。

我们可以直接告诉它要完成什么任务，由它自己分析代码库、修改文件、执行命令、运行测试，再根据结果继续调整。

我们不再需要手把手地告诉它每一步应该怎么做，而是可以把一个相对完整的目标交给它。

可以看到，大家就已经开始逐渐翻开权限将本地电脑交给 agent 来操控了（真的有人没开启 Full access 吗）。

## 四、personal agent

这也是最近国内外大厂在冲的一个产品类别，Muse、Dots、Grok bot、Cue、Today AI、Coze助手等等。

这类产品最明显的特征就是云端常驻，一直在线，有属于自己的电脑，由外部事件触发。

我最开始其实对于 personal agent 的理解就是一个个人长期使用的 agent，与那个本地的 coding agent 的差别也就是有个人记忆，越用越好用，越用越懂你的那种，但是经过这一久的国内外这些新兴 personal agent 的发布，我更新了我的理解，二者的区别，或者说，他们二者的使用场景是不一样的：

1. CodeX 这类 coding agent 的使用场景是高注意力、单一上下文的任务、工作，但是若是并行十几个任务，人的注意力和上下文是难以在十几个任务中穿梭的。并行的任务越多，上下文和注意力的切换成本就越高。
2. personal agent 就是来解放你的注意力和上下文的，你可以将大量任务委托给它去做，由这么一个主 agent 来替你承担这一部分，由它去盯着那些子 agent、任务。

当然，前提依然是模型在 agent 编排方面足够强，这也是这类产品在这个时间段冒出的原因，因为基础设施（模型、各种工程技术）已经达到这类产品的基础需求了。

这类产品就更上一层，我们已经可以放心将一些任务工作外包给 personal agent 去做了。

## 五、最后

在上一篇文章中，我提到，未来 Agent 可能会成为一部分应用的入口，用户不再需要亲自打开应用、寻找功能、一步步完成操作。

现在回过头看，这其实是同一件事的延伸。

从 Web 端的问答，到 Coding Agent 操作本地电脑，再到 Personal Agent 持续运行、主动跟进任务，变化的不仅是模型能力和产品形态，还有人类与软件之间的协作方式。

最开始，我们让模型告诉自己应该怎么做；后来，我们让模型替自己执行；再后来，我们希望它能够在授权范围内，持续把事情推进下去。

**当用户开始把执行权交给 Agent，应用就不再一定是交互的起点；当用户开始把任务的持续推进也交给 Agent，注意力本身就成为了 Agent 需要替用户管理的资源。**

而这一切的前提，是我们逐渐相信它能够把事情做好，并且在事情没有按预期发展时，仍然能够被约束、被监督、被纠正。

从这个角度看，Agent 产品形态的演化，本质上是人类逐渐愿意把更多自主权交给机器的过程。
